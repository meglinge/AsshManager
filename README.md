# AsshManager

面向团队的在线 SSH 管理与远程 MCP 服务。中文 Web 控制台、在线注册、独立个人/团队工作空间、逐台设备授权、可撤销的个人 MCP 令牌。

参考 [bvisible/mcp-ssh-manager](https://github.com/bvisible/mcp-ssh-manager) 的 SSH 工具、主机校验与审计思路，**重新实现多租户服务**，不是将其单用户控制台直接开放到公网，也不宣称兼容它的全部 37 个工具。没有复制其源代码。

> 当前是可运行的初始版本，不是经过独立安全审计的生产 SaaS。预览环境不要添加重要生产凭据。生产开放注册之前必须完成文末的安全准备。

## 已实现

- 在线注册（默认无需邮箱验证）、可选强制邮箱验证、登录、7 天服务端会话、退出、修改密码和邮件找回密码（撤销旧会话和全部 MCP 令牌）。
- 创建团队、邮件邀请/确认接受/撤销邀请、移除成员；所有者/管理员/普通成员三类角色。
- SSH 设备增删改、密码或带口令私钥认证、搜索、连接检测。不再设置环境分类。
- 每台团队设备可授权给指定成员或全体成员，个人设备仅自己可用。
- Web 命令终端（一次性命令，不是 PTY）、SFTP 目录浏览/文本读写。
- Streamable HTTP MCP `/mcp`，每个请求都校验 Bearer 令牌和当前设备权限。
- 令牌仅显示一次、只存 SHA-256 摘要、1–90 天有效期、可单独撤销。
- 操作审计、分页与当前页 JSON 导出；团队管理员可看团队日志，普通成员只能看自身日志。
- 响应式中文界面、空状态、错误提示、Docker 部署文件与 Amp Orb 自动启动配置。

## 本地运行

需要 Node.js **22.13+**（推荐 24 LTS）和 npm。数据库使用内置 SQLite，无需额外数据库服务。

```bash
npm ci
npm run build
npm start
```

本地默认监听 3000 端口。开发修改前端后重新运行 `npm run build`；`npm run dev` 仅自动重启后端。

自定义配置：复制 `.env.example` 为 `.env`，修改后运行：

```bash
node --env-file=.env --import tsx server/index.ts
```

`npm start` 不会隐式读取 `.env`。在 Orb 中运行 `.agents/setup` 后，使用 `amp orb services ensure` 启动预览；服务会读取 Amp 提供的 `PUBLIC_URL`，以确保 Cookie/Origin 匹配预览域名。

首次启动不创建默认管理员、共享密码或示例设备。默认填写姓名、邮箱与密码即可注册并进入工作空间，无需发送或点击验证邮件。每个用户拥有独立的个人空间。

### 邮箱验证开关

`EMAIL_VERIFICATION_REQUIRED` **默认 `false`**（不设置也是关闭）。仅显式设置 `true` 并重启服务后强制验证；Web 和 MCP 使用同一开关。关闭时，既有未验证账号也可以继续使用，不会被自动标记为“邮箱已验证”，设备权限和令牌检查不受影响。

启用后，注册不接受预先设置的密码，由邮箱持有人通过验证链接设置密码；未验证账号登录后只能验证邮箱或退出，不能访问设备、团队或 MCP。启用前请配置并测试 SMTP。关闭验证不证明邮箱归属，公开服务应考虑冒用邮箱注册的风险；邀请仍要求对应账号持有邮件中的一次性链接并明确接受。

### 邮件配置与升级

SMTP 为可选配置。生产环境未配置 `SMTP_HOST` 且邮箱验证关闭时可正常启动，注册、登录和 SSH/MCP 不依赖邮件；邮件发送禁用，也不会保存本地邮件文件。生产环境显式开启 `EMAIL_VERIFICATION_REQUIRED=true` 时必须配置 SMTP，否则启动报错，不会自动关闭验证。配置 `SMTP_HOST` 后必须提供 `SMTP_FROM`；`SMTP_PORT` 默认 587，如需认证则设置 `SMTP_USER` 与 `SMTP_PASSWORD`。465 使用 TLS，其他端口强制 STARTTLS，并校验证书；不提供关闭 TLS 校验的开关。发信域名还需在邮件供应商处完成 SPF/DKIM 等验证。

未配置 SMTP 的非生产环境会将邮件保存至 `DATA_DIR/mail/*.json`（目录 0700、文件 0600），**不会向真实邮箱发信**；邮件相关界面会明确提示。关闭邮箱验证时，注册、登录和 SSH/MCP 使用不依赖发信，但邮件邀请和找回密码仍需 SMTP 才能真实投递。此目录含验证/重置链接，只供部署管理员本地联调，不提供网页收件箱，不得通过静态服务暴露，测试后删除。设置了 SMTP 但投递失败不会退回本地模式。验证开启时的注册、申请验证和找回密码接口使用统一邮件回复，投递失败仅记录不含凭据的错误；邀请失败向管理员返回可重试错误。验证关闭时，重复邮箱注册会被拒绝，不覆盖原账号。当前没有持久化投递队列/自动重试，管理员应监控邮件服务失败并让用户重新申请。

邮箱验证链接有效期 24 小时，重置密码 30 分钟，邀请 7 天；链接随机值仅以 SHA-256 摘要存储。相同邮箱/用途一分钟内不重复发信，重新发送替换旧链接。打开链接只显示确认页面，GET 或邮件安全扫描不会消费链接；令牌放在 URL fragment 中，页面读取后从地址栏移除，不进入服务器访问日志。页面刷新后需从邮件重新打开链接。

找回密码不自动登录，成功后所有会话和 MCP 令牌立即失效。修改密码同时使未使用的验证/重置链接失效。通过验证或重置链接设置密码后才记录邮箱已验证。

升级会在事务中移除旧 `devices.environment` 字段并增加邮箱验证/邀请表，其他设备字段、加密凭据与成员关系不变。升级前请备份数据库和主密钥。**旧账号不会被自动标记为已验证**：默认关闭验证时沿用原密码和有效令牌；仅启用验证后需要完成验证才能访问。通过验证链接重设密码会撤销旧 MCP 令牌，需重新创建。先前已申请但尚未设置密码的账号可通过原验证邮件或找回密码完成设置。

## 使用路径

1. 注册并设置密码（默认无需邮箱验证）。创建团队并发送邀请；同事使用收件邮箱注册或登录，再打开邀请链接确认加入。邀请支持尚未注册的邮箱；若站点启用验证，先完成验证。
2. 在侧栏选择个人或团队工作空间。添加 SSH 主机、端口、用户、私钥/密码。
3. 从**可信服务器控制台**获取主机密钥指纹，例如：
   ```bash
   ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
   ```
   粘贴输出的 `SHA256:...`，点击测试连接。若 SSH 协商使用了其他主机密钥类型，应填写该类型的指纹或在服务器侧配置对应密钥类型；本服务不会自动信任或学习指纹。
4. 团队服务器在「访问权限」中授权指定成员；普通成员默认没有访问权。
5. 在 MCP 连接页创建个人令牌，为客户端配置正式服务地址和 Bearer 请求头。

### 权限模型

| 身份/授权            | 查看设备、检测连接 | 执行命令、读写文件 | 修改凭据和授权、删除设备 |
| -------------------- | ------------------ | ------------------ | ------------------------ |
| 个人设备所有者       | ✓                  | ✓                  | ✓                        |
| 团队所有者/管理员    | ✓                  | ✓                  | ✓                        |
| 团队普通成员，未授权 | —                  | —                  | —                        |
| 团队普通成员，仅查看 | ✓                  | —                  | —                        |
| 团队普通成员，可执行 | ✓                  | ✓                  | —                        |

全体成员授权与指定成员授权**叠加，取最高权限**，不支持显式 deny。全体成员授权会覆盖未来加入的成员。如需隔离部分成员，关闭全体授权，仅指定成员。

只有团队所有者能邀请/移除管理员；管理员只能邀请/移除普通成员，不能替换或撤销管理员邀请；所有者不能被移除。邀请必须由收件邮箱对应的账号通过一次性邮件链接确认，管理员无法直接添加成员；开启验证时还需验证邮箱。接受时复核邀请人的当前权限；移除邀请人会撤销其未接受的邀请。当前未提供所有权转移、团队删除及角色就地修改（可移除后以新角色邀请）。移除成员会清理其单独设备授权，再次加入不会恢复旧授权。团队设备归团队管理，创建者离开团队不会保留隐式权限。

“仅查看”不是通过命令黑名单伪装的只读 shell：它完全禁止命令和文件访问。“可执行”相当于配置的远程 SSH 用户权限，**不是沙箱**；恶意命令可能读取机器上的秘密或破坏数据。

## 远程 MCP

使用官方 TypeScript SDK，无状态 Streamable HTTP，POST `/mcp`。支持自定义 Bearer 请求头的客户端配置示例：

```json
{
  "mcpServers": {
    "assh-manager": {
      "type": "http",
      "url": "https://ssh.example.com/mcp",
      "headers": { "Authorization": "Bearer <YOUR_MCP_TOKEN>" }
    }
  }
}
```

不同客户端格式可能不同。只支持 OAuth、不支持自定义请求头的客户端当前不适用。Amp 预览 Portal 本身还有 Amp 登录保护，**不能将预览 URL 当作已公开部署的 MCP 地址**；外部 AI 客户端应连接自行部署的正式域名。测试已用官方 MCP 客户端直接对本地服务完成初始化、工具发现与真实 SSH 调用。

| 工具                 | 参数                                                      | 最低设备/令牌权限        |
| -------------------- | --------------------------------------------------------- | ------------------------ |
| `ssh_list_servers`   | 无                                                        | 有效令牌，仅返回可见设备 |
| `ssh_ping`           | `server_id`                                               | 查看 / read              |
| `ssh_execute`        | `server_id`, `command`, `timeout`（秒，1–60，默认 30）    | 执行 / execute           |
| `ssh_list_directory` | `server_id`, `path`（绝对路径）                           | 执行 / execute           |
| `ssh_read_file`      | `server_id`, `path`                                       | 执行 / execute           |
| `ssh_write_file`     | `server_id`, `path`, `content`, `overwrite`（默认 false） | 执行 / execute           |

执行返回 stdout、stderr、exitCode 和 signal。读取/输出上限 256 KiB，写入上限 64 KiB；只面向 UTF-8 文本。目录最多返回 1000 条并标注截断。默认写入使用独占创建，覆盖必须显式开启且非原子操作。每用户最多 4 个、进程合计最多 32 个 SSH 操作。超时或撤权会关闭连接，**不保证杀死远程进程，也不能撤回已执行操作**。活跃连接每 500ms 复核授权和令牌；每次新请求即时复核。

## 安全边界与部署

- SSH 凭据用 AES-256-GCM 加密，每条独立随机 IV，以设备 ID 作 AAD，防止密文跨设备置换。API 永不返回凭据。数据库主文件权限 0600，新建数据目录 0700。
- 开发环境自动生成 `data/development.key`。生产设置 `NODE_ENV=production`、HTTPS `PUBLIC_URL` 和 **64 个十六进制字符**的 `ENCRYPTION_KEY`，否则拒绝启动。使用 `openssl rand -hex 32` 生成并存入密钥管理系统；不要提交到仓库。
- 丢失或直接更换加密密钥将无法解密旧凭据。目前无在线主密钥轮换工具，轮换需规划解密重加密迁移；备份数据库与密钥，但分开保管。可在停止写入期间备份，或使用 SQLite 在线备份 API，不能仅复制活跃数据库主文件而忽略 WAL。
- 登录密码以独立盐 scrypt 哈希；HttpOnly / SameSite=Strict 会话 Cookie，HTTPS URL 自动启用 Secure；API 写操作要求匹配 Origin；MCP 仅接受 Bearer，不接受会话 Cookie。
- 所有 SSH 连接固定主机指纹；不使用 TOFU、不转发 SSH agent、不自动 sudo。
- 默认只允许公网单播 IP；禁止私网/回环/特殊网段。部署管理员可用 `SSH_ALLOWED_CIDRS` 显式放开特定私网。DNS 全部结果经过验证后用固定 IP 建连，避免二次解析；链路本地/元数据地址永不放开。**这不是完整的出站防火墙**：公网目标默认允许，专用私网网段是全服务配置。生产必须部署独立 SSH 执行网络，限制可达目标与端口，隔离管理数据库、密钥服务和云元数据，避免成为网络探测代理。
- 请求限流为单进程内存计数。仅在应用只能从一个受信反向代理访问时设置 `TRUST_PROXY=1`，否则客户端可能伪造转发地址。生产还应在入口提供全局限流与防滥用。
- 审计只存元数据、权限变更、命令摘要与执行结果；不存原始命令、文件路径/内容或输出（设备名称、主机等元数据非秘密）。SQLite 中审计记录没有 API 删除入口，但**不是防篡改日志**；需接入外部只追加审计存储和保留策略。进程崩溃可能留下仅有 started 的未完成事件。

### Docker

```bash
# 先在环境或 .env 中提供 HTTPS PUBLIC_URL 与 ENCRYPTION_KEY；SMTP 按需配置
docker compose up --build -d
```

容器以非 root 用户运行，监听仅映射到宿主回环 3000 端口；需自行配置 HTTPS 反向代理。持久化卷 `assh-data` 保存 SQLite。Compose 文件是部署模板，运行它会创建实际服务，需由部署负责人在目标环境执行。

### 正式开放注册前仍需完成

生产邮件投递验证和失败监控、MFA/SSO、OAuth MCP 接入、防机器人注册、账户/存储配额、外部防篡改审计、灾备演练，以及独立安全审查。可设 `REGISTRATION_ENABLED=false` 关闭新注册，不影响既有账号验证和找回密码。

当前为单进程 SQLite 部署；不适用于多副本共享网络文件系统。需要高可用时，先迁移到 Postgres，并将会话、限流、连接配额和任务状态迁移到共享后端。此版本没有交互式 PTY、二进制传输、隧道、批量任务和危险命令审批；不要误认为已提供。

## 验证

Linux 安装 `openssh-server`，并确保 `/run/sshd` 存在。测试以当前普通用户启动隔离的本地 OpenSSH，生成临时密钥，使用真实命令与 SFTP；结束时清理。不会连接你添加的任何设备。

```bash
npm test
npm run build
```

测试覆盖默认免验证注册、邮箱验证开关对 Web/MCP 的一致控制、链接过期/用途隔离/并发重复消费、密码重置和凭据撤销、邀请接受/错邮箱/撤销/邀请人离开、投递失败、HTTP 账户/CSRF、团队默认拒绝与授权叠加、跨租户隔离、MCP 初始化/工具发现、令牌范围/过期/撤销、成员移除、真实 SSH/SFTP、主机指纹不匹配、输出/超时限制、网络特殊地址、凭据加密与 SQLite 升级持久化。邮件功能测试使用隔离的邮件传输替身，不会向真实邮箱发信。

## 代码组织

`server/app.ts` 账户和资源 API；`server/invitations.ts` 团队邀请；`server/mail.ts` SMTP/本地邮件传输；`server/security.ts` 加密与共同权限边界；`server/ssh.ts` 受控 SSH/SFTP 执行；`server/mcp.ts` 协议入口；`server/store.ts` SQLite schema。`web/` 为 React 中文界面，`tests/` 为真实链路验证。
